What It Does

Opens two Agilent GC/MS .M method folders side by side and presents a structured, diff-highlighted comparison of every parameter — injection, headspace, autosampler, GC oven/inlet/ALS, and MS acquisition settings.

Designed for field and R&D engineers who need to quickly identify differences between methods: comparing a customer’s method against a reference, auditing method drift across instrument versions, or reviewing a method handed off by a colleague.

How to Use

1
Launch methcompare.exe — no installation required.
2
Click Browse… to open the folder browser. Navigate to a folder containing .M method folders. Select one method for Method A, or Ctrl + click two methods to assign them to A and B together. Click Open.
3
If only Method A was loaded, click Browse… again to load Method B. You can also type or paste a full path directly into either method path field.
4
Click Compare to run the comparison.
5
Review the comparison table. Parameters are grouped by section. Rows where values differ are highlighted. Double-click highlighted rows marked with a ↵ indicator to open a detail popup.
Tip: Use the Diff only toggle to hide matching rows and focus on what changed. The Recent… button quickly reloads a previously compared pair of methods.

UI Features

Colour Coding

  • Yellow — values differ between the two methods
  • Salmon — transition/ion present in Method A only
  • Mint — transition/ion present in Method B only
  • Amber — same precursor, different product mass (MRM/SIM)

Collapsing Sections

Double-click any section header to collapse or expand it. Use the Collapse All / Expand All buttons in the toolbar to toggle all sections at once.

Detail Popups

Several rows summarise a list of items. Double-click any such row (marked with a ↵ indicator) to open a detail popup:

  • MRM / SIM / dSIM transitions — full per-transition table with Compound, Precursor, Product (if MRM), CE, Dwell, RT, and per-row status colour coding. Filter buttons isolate Modified, Mass changed, Only in A/B, or Match rows. A live Search box filters all visible columns.
  • Timed SIM (TQ dSIM) — segment-per-ion view showing segment number, start time, m/z, and dwell for both methods. Used when a TQ method contains many MS1SIM time segments.
  • SIM groups (SQ 5975/5977) — hierarchical view: group header rows show Group Name, ion count, Start Time, Resolution, and EMV setting; expandable ion child rows show Compound, m/z, and Dwell per method.
  • MS timed events — flat list sorted by time showing Event type, Time (min), and the value in each method. Filter buttons (All / Modified / Only in A / Only in B / Match) and a live search box are on separate rows so they remain accessible at any window width.

Differences Only

Click the Diff only button (turns orange) to hide rows where both methods have the same value. Click again (Show all, turns blue) to restore all rows. Rows where a parameter is present in one method but absent in the other are always shown regardless of this toggle.

Advanced Features

The parsers handle a range of edge cases that arise with real-world Agilent methods. Several of these required detailed knowledge of the binary and XML method formats to implement correctly.

TQ

Mixed Scan Types per Time Segment

A single TQ method may mix MRM, MS2SIM, ProductIon, PrecursorIon, NeutralLoss, and NeutralGain scan segments within the same method. Each segment is classified by its dominant scan type. Embedded survey scans are extracted and shown separately with their own data storage and detection threshold settings.

TQ

dSIM / Timed SIM Popup

TQ methods with large numbers of MS1SIM time segments (e.g. 56-segment VOCS or 8-segment FFAP methods) open a dedicated Timed SIM detail popup. Each ion is shown with its segment number, start time, m/z, and dwell for both methods, with full filter and search support.

TQ

Neutral Loss & Neutral Gain

TQ Neutral Loss and Neutral Gain scan modes display the Q1 scan range, step size, and per-step records showing the offset (Da) and collision energy (eV). The offset is derived automatically from the Q1/Q2 mass differential in the method XML — no manual entry required.

5987 · 5977 · TQ

Timed Events — All Three MS Families

MS timed events are parsed and compared for all supported MS types:

  • 5987: Gain factor, Valve open/close, MS On/Off, MS Source Temp, Delta EMV
  • 5977 SQ: Detector On/Off, Gain factor, EI/CI Cal valves, MS Source Temp
  • TQ 7000/7010: Valve, MS On/Off, MSE register writes
5987

Delta EMV Timed Events

5987 methods configured with Set EM in Timed Events using Delta EMV mode are fully supported. Each time-point shows the voltage offset (V) applied to the detector, read from the deltaEMVSetting field in the method XML. Displayed alongside Gain Factor events for easy comparison.

5977 SQ

SIM/Scan Mode

SQ 5977 methods using Acquisition Mode 3 (SIM/Scan) are correctly labelled. Both full-scan and SIM settings are shown; SIM groups are only displayed for acquisition modes that actually include SIM (modes 1 and 3), preventing spurious group rows from appearing in Profile or Scan-only methods.

All

Cross-instrument Comparison

Comparing methods from different instrument families (e.g. a 5977 SIM method against a TQ dMRM method) is handled gracefully. Each instrument’s parameters are parsed independently; instrument-specific sections appear in one column only, while shared parameters (GC, injection, sampler) are compared side by side.

TQ · SIM

Transition Count Pluralisation

Row summaries use correct singular/plural forms: 1 mass changed vs. 2 masses changed, avoiding misleading grammar when only a single ion mass differs between methods. Applies to both MRM transition lists and SIM ion lists.

Filter bar layout: All transition, timed SIM, and timed events popups place the status filter buttons (All / Modified / Only in A / Only in B / Match) on a separate row above the search box, so both remain fully accessible even at minimum window width.

Notes & Limitations

  • GC timed events (e.g. post-run valve switches) are not currently compared — only static GC parameters are shown.
  • The tool supports viewing a single method or comparing two methods side by side. Comparing more than two methods at once is not supported.
  • The tool reads method files directly — it does not connect to an instrument or data system.
  • Methods from offline/simulation mode may contain placeholder values.
